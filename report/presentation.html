System Overview

Motivation & Project Scope

Problem & Solution
Problem Statement

Academic study of graph theory is conventionally constrained to static blackboards and abstract adjacency matrices. Learners often fail to develop a tangible intuition for search-frontier dynamics, heuristic bias, and priority queue edge relaxation under physical terrain constraints.

Most existing web tools rely on basic 2D DOM tables with colored blocks that lack realistic spatial modeling and GPU acceleration.

System Scope & Deliverables
  • Interactive 3D Simulation: Models a 25×50 grid as a miniature city diorama (buildings as obstacles, parks as weights).
  • Algorithm Suite: Fully implements 6 graph traversal engines (BFS, DFS, Dijkstra, A*, Greedy, Bidirectional).
  • Procedural Maze Generation: Implements 5 algorithms with an autonomous reachability validator.
  • Empirical Analytics: Live capture of nodes visited, path cost, path length, and sub-millisecond execution times.
  • Cloud Grid Persistence: Full-stack REST API and database integration for saving and sharing board layouts.

Algorithmic Suite

Pathfinding Algorithms & Heuristics

Theoretical Matrix
Algorithm Data Structure Supports Weights Guarantees Shortest Path Time Complexity Space Complexity
Breadth-First Search (BFS) Queue (FIFO) No Yes (Unweighted) O(V + E) O(V)
Depth-First Search (DFS) Stack (LIFO) No No O(V + E) O(V)
Dijkstra's Algorithm Min-Heap (Priority Queue) Yes Yes O((V + E) log V) O(V)
A* Search Min-Heap (f = g + h) Yes Yes (Admissible) O((V + E) log V) O(V)
Greedy Best-First Min-Heap (f = h) No No O((V + E) log V) O(V)
Bidirectional BFS 2 × Queues + 2 × Sets No Yes (Unweighted) O(V + E) O(V)
Dijkstra vs. A* Search

Dijkstra expands uniformly in all directions (\(g(n)\) only). A* incorporates a Manhattan heuristic (\(f(n) = g(n) + h(n)\)), directing exploration toward the goal and exploring up to 70% fewer nodes with identical optimality.

Heuristic Admissibility Guard

Our 4-way grid uses Manhattan Distance: \(h(n) = |\Delta r| + |\Delta c|\). We multiply this by the minimum terrain weight on the board, ensuring \(h(n) \le h^*(n)\) (strictly admissible and consistent).

Procedural Generation

Maze Subsystem & Solvability Engine

Graph Theory
Recursive Division

Chamber subdivision model. Recursively adds horizontal and vertical dividing walls with single passage gaps, creating structured rooms and corridors.

Recursive Backtracker

Randomized DFS moving 2 cells at a time. Backtracks using a stack upon dead ends. Generates deep, winding corridors with high solution path depth.

Randomized Kruskal's

Constructs a Minimum Spanning Tree (MST). Uses Disjoint Set Union (Union-Find) with Path Compression & Rank to unite passages without cycles.

Autonomous Solvability Engine: 0-1 Dijkstra Post-Processor

Random generation can inadvertently isolate the target node. The custom ensureReachableMaze subsystem runs a BFS reachability test. If disconnected, it executes a 0-1 Dijkstra search (open passages cost 0, walls cost 1) to identify the absolute minimum sequence of blocking walls and surgically carves out an open path.

Performance Engineering

Key Engineering Challenges & Solutions

System Optimizations
1. WebGL Draw Call Bottleneck

Challenge: Rendering 1,250 individual Three.js Mesh instances created 1,250 draw calls per frame, degrading frame rates to 15 FPS.
Solution: Migrated to THREE.InstancedMesh across 3 geometry pools (roads, buildings, trees), collapsing 1,250 draw calls into just 3 draw calls.

2. React State Thrashing During Playback

Challenge: Triggering React component re-renders per visited node locked the browser main thread.
Solution: Decoupled animation from UI state. GSAP writes directly to pre-allocated Float32Array buffers read by Three.js per frame without React involvement.

3. Min-Heap Priority Queue Invalidation

Challenge: In-place mutation of a node's distance in binary heap corrupts the heap invariant without an expensive \(O(N)\) rebuild.
Solution: Stored immutable snapshot objects { node, distance } and added a stale-entry check upon pop: if (d !== current.distance) continue;.

4. Asynchronous Race Conditions

Challenge: Rapid user clicks on "Run" or "Reset" during playback left orphaned timer callbacks corrupting the board.
Solution: Implemented a monotonic runId check on all async callbacks to drop stale executions immediately.

Project Overview

Motivation & Objectives

Problem Statement
Problem Statement

Textbook graph algorithms are taught using static node-edge diagrams and abstract matrices. Students often lack an intuitive understanding of search-frontier expansion, heuristic guidance, and edge relaxation under real spatial constraints.

Most existing web visualizers rely on basic 2D DOM tables with colored boxes that fail to reflect physical routing scenarios.

Core Objectives
  • Algorithm Diversity: Implement 6 foundational algorithms (BFS, DFS, Dijkstra, A*, Greedy, Bidirectional BFS).
  • 3D Spatial Realism: Render a 25×50 grid as a miniature city diorama (buildings as obstacles, parks as weights).
  • Procedural Mazes: Generate solvable mazes via Division, Backtracker, Prim's, and Kruskal's methods.
  • Empirical Analytics: Measure execution time, nodes visited, path length, and traversal cost in real time.

System Architecture

Execution & Animation Pipeline

Separation of Concerns
1

Pure Synchronous Algorithm Run (~2ms)

Pure mathematical traversal in memory. Generates deterministic AlgorithmResult containing visited nodes and final path.

2

AnimationEngine (GSAP Timeline)

Builds a staggered timeline writing per-node phases, target heights, and emissive values into flat Float32Array buffers.

3

Three.js WebGL Render Loop (60 FPS)

useFrame() reads shared buffers every frame. Spring physics smoothly interpolates building and road elevations.

4

State Baking & Resource Release

Terminal state is baked back into the Zustand store upon completion, freeing memory buffers.

Key Architectural Advantages
  • Zero Garbage Collection Stutter: Avoids triggering React state re-renders during the 1,250-node traversal loop.
  • Dynamic Speed Scaling: timeline.timeScale() adjusts playback speed live without restarting.
  • Concurrency Safety: A monotonic runId invalidates previous runs when user triggers new actions.
  • Accurate Benchmarks: Algorithm execution time is measured via performance.now() before rendering begins.

Algorithm Analysis

Pathfinding Algorithms Comparison

Complexity Matrix
Algorithm Data Structure Weights Optimal Path Time Complexity Space Complexity
Breadth-First Search (BFS) Queue (FIFO) No Yes (Unweighted) O(V + E) O(V)
Depth-First Search (DFS) Stack (LIFO) No No O(V + E) O(V)
Dijkstra's Algorithm Min-Heap (Priority Queue) Yes Yes O((V + E) log V) O(V)
A* Search Min-Heap (f = g + h) Yes Yes O((V + E) log V) O(V)
Greedy Best-First Min-Heap (f = h) No No O((V + E) log V) O(V)
Bidirectional BFS 2 × Queues + 2 × Sets No Yes (Unweighted) O(V + E) O(V)
Dijkstra vs. A* Search

Dijkstra expands uniformly in all directions (\(g(n)\) only). A* adds a Manhattan heuristic (\(f(n) = g(n) + h(n)\)), directing exploration toward the goal and exploring up to 70% fewer nodes with identical optimality.

Heuristic Admissibility Guard

Our 4-way grid uses Manhattan Distance: \(h(n) = |\Delta r| + |\Delta c|\). We multiply this by the minimum terrain weight on the board, ensuring \(h(n) \le h^*(n)\) (strictly admissible and consistent).

Procedural Generation

Maze Generators & Solvability Guard

Graph Theory
Recursive Division

Subdivides space by adding horizontal/vertical dividing walls with random passage gaps. Produces structured chambers and distinct corridors.

Recursive Backtracker

Randomized DFS moving 2 cells at a time. Backtracks using a stack upon encountering dead ends. Creates deep, winding paths with high branch depth.

Randomized Kruskal's

Builds a Minimum Spanning Tree (MST). Uses Disjoint Set Union (Union-Find) with Path Compression and Union by Rank to unite passages without cycles.

Automated Solvability Guard: 0-1 Dijkstra Post-Processor

Random generation can inadvertently isolate the target. Our ensureReachableMaze algorithm first runs a BFS reachability test. If blocked, it executes a 0-1 Dijkstra search (open passages cost 0, walls cost 1) to identify the minimum number of walls blocking reachability and surgically carves out an open path.

Engineering Challenges

Difficulties Faced & Solutions

System Optimization
1. WebGL 60 FPS Draw Call Bottleneck

Challenge: Rendering 1,250 individual 3D mesh instances triggered 1,250 draw calls per frame, dropping frame rates to 15 FPS.
Solution: Migrated to THREE.InstancedMesh across 3 geometry pools (roads, buildings, trees), reducing 1,250 draw calls to just 3 draw calls.

2. React Re-render Thrashing

Challenge: Updating React state during node exploration locked the browser main thread.
Solution: Decoupled animation from state. GSAP writes directly to pre-allocated Float32Array buffers read by Three.js per frame without React involvement.

3. Min-Heap Priority Queue Invalidation

Challenge: In-place mutation of a node's distance in binary heap corrupts the heap order without an expensive \(O(N)\) rebuild.
Solution: Stored immutable snapshot objects { node, distance } and added a stale-entry check upon pop (if (d !== current.distance) continue;).

4. Asynchronous Race Conditions

Challenge: Rapid user clicks on "Run" or "Reset" during playback created conflicting ghost timers.
Solution: Implemented a monotonic runId check on all async callbacks to drop stale executions immediately.

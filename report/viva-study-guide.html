3. Grid Data Model

GridNode — The Core Data Unit

Every cell in the 25×50 grid is a GridNode object:

GridNode {
  row, col          // Position in grid
  type              // 'empty' | 'wall' | 'start' | 'end' | 'weight'
  weight            // 1 for normal, 5 for weighted terrain
  distance          // g(n): cost from start (init: Infinity)
  heuristic         // h(n): estimated cost to end (Manhattan)
  totalCost         // f(n) = g(n) + h(n)
  isVisited         // Has algorithm processed this node?
  previousNode      // Pointer to reconstruct path
  visualState       // 'unvisited' | 'visited' | 'path' | 'current'
}

Movement Model

4-directional only: Up, Right, Down, Left. No diagonal movement.

Neighbor order: Consistent across all algorithms — Up → Right → Down → Left.

Wall blocking: If neighbor.type === 'wall', the neighbor is skipped entirely.

Path Reconstruction

All algorithms use the same reconstructPath(endNode) function:

function reconstructPath(endNode):
    path = []
    current = endNode
    while current !== null:
        path.unshift(current)       // Prepend to front
        current = current.previousNode
    return path

4. Core Data Structures

MinHeap (Priority Queue)

Used by: Dijkstra, A*, Greedy

Type: Binary min-heap with custom comparator

  • push(val) → sift up — O(log n)
  • pop() → swap root with last, sift down — O(log n)
  • peek() → return root — O(1)

Key detail: Uses immutable snapshot entries to prevent heap corruption when node distances are updated in-place.

UnionFind (Disjoint Set Union)

Used by: Kruskal's Maze Generator

Optimizations:

  • Path Compression: find(x) flattens tree
  • Union by Rank: attaches smaller tree under larger

Complexity: Nearly O(1) per operation (amortized O(α(n)) — inverse Ackermann).

5. All 6 Pathfinding Algorithms

5.1 Breadth-First Search (BFS)

Queue (FIFO) No Weights Shortest Path ✓

How it works: Explores all neighbors at the current depth level before moving deeper. Think of it as a wave expanding outward from the start — like dropping a stone in water.

Pseudocode

function BFS(grid, start, end):
    queue = [start]
    start.isVisited = true
    start.distance = 0
    
    while queue is not empty:
        current = queue.dequeue()     // Remove from FRONT
        
        if current === end:
            return reconstructPath(end)   // Found!
        
        for each neighbor in getNeighbors(current):  // Up, Right, Down, Left
            if !neighbor.isVisited AND neighbor.type ≠ 'wall':
                neighbor.isVisited = true
                neighbor.distance = current.distance + 1
                neighbor.previousNode = current
                queue.enqueue(neighbor)     // Add to BACK
    
    return "No path found"

Why it guarantees shortest path (unweighted)

BFS explores level-by-level. Every node at distance d is processed before any node at distance d+1. So the first time BFS reaches the end node, it found the path with the fewest hops.

Time: O(V + E) = O(R × C)   |   Space: O(V) = O(R × C)

5.2 Depth-First Search (DFS)

Stack (LIFO) No Weights NOT Shortest Path ✗

How it works: Dives as deep as possible down one branch before backtracking. Think of it as exploring a maze by always turning the same direction until you hit a dead end.

Pseudocode

function DFS(grid, start, end):
    stack = [start]
    
    while stack is not empty:
        current = stack.pop()          // Remove from TOP
        
        if current.isVisited: continue
        current.isVisited = true
        
        if current === end:
            return reconstructPath(end)
        
        for each neighbor in reverse(getNeighbors(current)):
            if !neighbor.isVisited AND neighbor.type ≠ 'wall':
                neighbor.previousNode = current
                stack.push(neighbor)    // Add to TOP
    
    return "No path found"

Why it does NOT guarantee shortest path

DFS commits to one deep branch. It may find the end via a long, winding route while a much shorter path existed elsewhere. It depends on which direction it explores first.

Time: O(V + E) = O(R × C)   |   Space: O(V) = O(R × C)

5.3 Dijkstra's Algorithm

Min-Heap (Priority Queue) Handles Weights ✓ Shortest Path ✓

How it works: Always expands the node with the smallest known distance from start. Discovers shortest paths layer-by-layer but accounts for weighted edges.

Key Concept — Edge Relaxation

If   g(current) + weight(neighbor) < g(neighbor)   →   Update g(neighbor)

Pseudocode

function Dijkstra(grid, start, end):
    start.distance = 0
    pq = MinHeap()
    pq.push({node: start, distance: 0})
    
    while pq is not empty:
        {node: current, distance: d} = pq.pop()
        
        if d ≠ current.distance OR current.isVisited: continue  // Stale entry
        if current.distance === Infinity: break              // Unreachable
        current.isVisited = true
        
        if current === end:
            return reconstructPath(end)
        
        for each neighbor in getNeighbors(current):
            if !neighbor.isVisited AND neighbor.type ≠ 'wall':
                newDist = current.distance + neighbor.weight
                if newDist < neighbor.distance:    // RELAXATION
                    neighbor.distance = newDist
                    neighbor.previousNode = current
                    pq.push({node: neighbor, distance: newDist})
    
    return "No path found"

Stale Entry Handling

When a node's distance is updated (relaxed), a new entry is pushed into the heap. The old entry becomes "stale". When popped, the check d ≠ current.distance discards it.

Time: O((V + E) log V)   |   Space: O(V)

5.4 A* Search

Min-Heap (f = g + h) Handles Weights ✓ Shortest Path ✓

How it works: Like Dijkstra, but uses a heuristic to guide the search toward the goal. Expands the node with the smallest f(n) = g(n) + h(n).

f(n) = g(n) + h(n)
g(n) = actual cost from start   |   h(n) = estimated cost to end (Manhattan distance)

Manhattan Distance Heuristic

h(node) = |node.row - end.row| + |node.col - end.col|

Why Manhattan? Our grid only allows 4-directional movement. Manhattan distance is admissible (never overestimates) and consistent, guaranteeing optimality.

Admissibility Guard (from our code)

Our A* implementation scans the grid for the minimum cell weight and multiplies: h(n) = manhattanDistance × minWeight. This ensures the heuristic stays admissible even with weighted terrain.

Why A* is faster than Dijkstra

A* explores fewer nodes because the heuristic guides it toward the goal. Dijkstra blindly expands in all directions (like a circle), while A* biases toward the goal direction (like an ellipse).

Time: O((V + E) log V)   |   Space: O(V)

5.5 Greedy Best-First Search

Min-Heap (f = h only) Ignores Weights NOT Shortest Path ✗

How it works: Always expands the node that appears closest to the goal (smallest h(n)). Very fast, but easily tricked by obstacles.

f(n) = h(n) only   (ignores g(n) entirely)

Why it fails

Greedy rushes directly toward the goal. If a wall blocks the direct path, it gets stuck exploring around the obstacle, often finding a suboptimal route. It doesn't track cumulative costs, so it can't guarantee optimality.

Uses a Discovered Set

Unlike Dijkstra/A*, Greedy uses a Set<GridNode> to prevent re-enqueueing the same node (since there's no relaxation step).

Time: O((V + E) log V)   |   Space: O(V)

5.6 Bidirectional BFS

2 × Queue + 2 × Set No Weights Shortest Path ✓

How it works: Runs two simultaneous BFS searches — one from start, one from end. When the two frontiers collide, merge the paths.

Why it's faster than regular BFS

Regular BFS explores a circle of radius r: area = π·r²

Bidirectional explores two circles of radius r/2: area = 2 × π·(r/2)² = π·r²/2

→ Explores roughly HALF the nodes in practice!

Path Merging

// When frontiers collide at meetingNode:
forwardPath  = trace(meetingNode → start)  using parentForward map
backwardPath = trace(meetingNode → end)    using parentBackward map
fullPath     = [...forwardPath, ...backwardPath]
Time: O(V + E)   |   Space: O(V)   (but ~50% fewer nodes explored)

6. Algorithm Comparison

Algorithm Data Structure Weighted? Optimal? Time Best For
BFS Queue (FIFO) No Yes O(V+E) Unweighted shortest path
DFS Stack (LIFO) No No O(V+E) Maze solving, connectivity
Dijkstra Min-Heap Yes Yes O((V+E) log V) Weighted shortest path
A* Min-Heap (g+h) Yes Yes O((V+E) log V) Fastest optimal weighted
Greedy Min-Heap (h) No No O((V+E) log V) Quick approximation
Bidirectional 2 × Queue No Yes O(V+E) Large unweighted graphs

When to Use Which?

  • No weights, need shortest path → BFS (simple) or Bidirectional BFS (faster)
  • Weighted edges, need optimal → A* (with good heuristic) or Dijkstra (no heuristic available)
  • Just need any path, fast → Greedy or DFS
  • Large graph, unweighted → Bidirectional BFS (explores ~50% fewer nodes)

A* vs Dijkstra — The Key Difference

Expands in all directions equally (circle-like). No knowledge of where the goal is.

Guaranteed optimal ✓

A*

Priority = g(n) + h(n)

Guided toward the goal by the heuristic. Explores fewer nodes, same optimal result.

Guaranteed optimal ✓ (if h is admissible)

7. Maze Generators

Generator Strategy How It Works Solvable?
Recursive Division Chamber Subdivision Starts with border walls. Recursively divides space with horizontal or vertical walls, leaving one random passage gap. Yes
Recursive Backtracker Randomized DFS Fills grid with walls. Picks random start, carves corridors by moving 2 cells at a time. Backtracks via stack when stuck. Yes
Randomized Prim's Growing Tree / MST Fills with walls. Picks seed cell. Maintains frontier list. Randomly connects frontier to existing maze by carving intervening wall. Yes
Randomized Kruskal's Union-Find / MST Fills with walls. Marks odd cells as passages. Shuffles all wall edges (Fisher-Yates). Removes wall if it connects two disconnected regions. Yes
Random Scatter Bernoulli Trials Each cell independently has 30% chance of becoming a wall. Start and end are always kept open. No guarantee

Solvability Enforcement — ensureReachableMaze

The first four generators call ensureReachableMaze() which:

  1. Builds a passability map — 2D boolean grid from maze steps
  2. Runs BFS from start → end to check if a path exists
  3. If blocked, runs 0-1 Dijkstra to find the minimum number of walls to carve to create a connection
  4. Appends the carved passages to the maze steps

This guarantees every generated maze (except Random Scatter) is always solvable.

Algorithm Questions

Explain how BFS works.

BFS uses a FIFO queue. It starts from the source, marks it visited, and enqueues it. Then it repeatedly dequeues the front node, adds unvisited non-wall neighbors to the back of the queue (marking them visited immediately), and continues until it finds the destination or exhausts the queue. It explores level-by-level, so it guarantees the shortest path on unweighted graphs.

Why does BFS guarantee shortest path but DFS does not?

BFS explores all nodes at distance d before any node at distance d+1 — it spreads like a wave. So the first time it reaches the end, it found the minimum number of hops. DFS, on the other hand, commits deeply to one branch. It might find the end via a long winding path while a much shorter path existed in a different direction.

What is the difference between BFS and DFS in terms of data structure?

BFS uses a Queue (FIFO — First In, First Out). DFS uses a Stack (LIFO — Last In, First Out). The queue ensures breadth-first exploration; the stack ensures depth-first exploration.

Explain Dijkstra's algorithm.

Dijkstra uses a min-heap priority queue. It starts with the source at distance 0, all others at infinity. It repeatedly extracts the node with the smallest distance, then "relaxes" all its neighbors: if current.distance + edge_weight < neighbor.distance, update the neighbor's distance and push it to the heap. This guarantees shortest paths with non-negative edge weights.

What is edge relaxation?

Relaxation is the process of checking whether we've found a shorter path to a node. If the new distance (current.distance + neighbor.weight) is less than the previously known distance, we update it. It's called "relaxation" because we're gradually tightening the upper bound on the shortest distance.

What is A* and how does it differ from Dijkstra?

A* is Dijkstra plus a heuristic. While Dijkstra uses f(n) = g(n) as priority (actual cost from start), A* uses f(n) = g(n) + h(n) where h(n) is an estimated cost to the goal. The heuristic guides the search toward the destination, so A* typically explores far fewer nodes while still finding the optimal path — provided the heuristic is admissible (never overestimates).

What heuristic do you use in A* and why?

Manhattan distance: |row₁ - row₂| + |col₁ - col₂|. We use it because our grid only allows 4-directional movement (no diagonals). Manhattan distance exactly measures the minimum number of steps needed on such a grid, making it both admissible and consistent — which guarantees A* finds the optimal path.

What does "admissible" mean for a heuristic?

An admissible heuristic never overestimates the actual cost to reach the goal. It's always ≤ the true shortest distance. This is essential for A* to guarantee optimality. If the heuristic overestimates, A* might skip the optimal path and settle for a suboptimal one.

What is Greedy Best-First Search and why is it not optimal?

Greedy uses f(n) = h(n) only — just the heuristic estimate, completely ignoring the actual cost from start (g(n)). It rushes directly toward the goal, which is fast but easily fooled by obstacles. It might take a long detour around a wall instead of finding a shorter path that initially goes away from the goal.

How does Bidirectional BFS work and why is it faster?

It runs two BFS searches simultaneously — one from start expanding forward, one from end expanding backward. They alternate expanding one level at a time. When the two frontiers meet, we merge the paths. It's faster because instead of one BFS exploring a circle of radius r (area πr²), we have two circles of radius r/2 (total area πr²/2) — roughly half the nodes explored.

Which algorithms handle weighted edges and which don't?

Only Dijkstra and A* properly handle weighted edges — they account for node.weight when calculating distances. BFS, DFS, Greedy, and Bidirectional BFS treat all edges as weight 1.

What is the time complexity of BFS and DFS?

Both are O(V + E) where V is the number of vertices and E is the number of edges. For our grid, V = rows × cols and E ≈ 4V (each cell has up to 4 neighbors), so it's effectively O(R × C).

Why is Dijkstra's complexity O((V+E) log V)?

Each node can be pushed to the heap (O(log V) per push), and each edge can cause a relaxation that pushes to the heap. So we have at most V pops (O(log V) each) and E pushes (O(log V) each), giving O((V+E) log V).

Can Dijkstra handle negative weights?

No. Dijkstra assumes once a node is popped from the priority queue, its shortest distance is finalized. Negative weights can violate this assumption. For negative weights, you'd need Bellman-Ford (which we haven't implemented).

How do you handle stale entries in the priority queue?

When we relax a node, we push a new entry with the updated distance but don't remove the old entry. When we pop an entry, we check if its recorded distance matches the node's current distance. If they differ, the entry is stale and we skip it. This avoids the need for a decrease-key operation.

Data Structures

What is a MinHeap and how does it work?

A MinHeap is a complete binary tree where each parent is smaller than its children. It's stored as an array where parent of index i is at (i-1)/2, and children are at 2i+1 and 2i+2. Push adds to the end and "sifts up" (swaps with parent while smaller). Pop removes the root, moves the last element to root, and "sifts down" (swaps with smallest child). Both operations are O(log n).

What is Union-Find and where do you use it?

Union-Find (Disjoint Set Union) tracks which elements belong to connected groups. We use it in Kruskal's maze generator to track which cells are already connected. When considering removing a wall between two cells, we check if they're in the same set — if not, we remove the wall and union them. Path compression and union by rank make operations nearly O(1).

Why did you use immutable snapshot entries in the priority queue?

When we relax a node and update its distance, if we had mutable references in the heap, the heap order would be corrupted (a node's priority changed without the heap knowing). By pushing immutable snapshots {node, distance}, the old entry stays valid in the heap until popped, at which point we check if it's stale.

Maze Generation

How does Recursive Division maze work?

It starts with an empty grid bordered by walls. Then it recursively divides the space: pick a random horizontal or vertical line to draw a wall, leave one random gap as a passage. Repeat for each sub-chamber. This creates maze-like structures with corridors and rooms.

How does Recursive Backtracker maze work?

It fills the grid with walls, then performs a randomized DFS. It carves corridors by moving 2 cells at a time (to create walls between passages). When it reaches a dead end (no unvisited neighbors 2 cells away), it backtracks using a stack until it finds an unvisited neighbor. This creates long, winding corridors.

How do you ensure generated mazes are solvable?

After generating the maze, we run the ensureReachableMaze helper. It does a BFS from start to end. If the path exists, great. If not, it runs a 0-1 Dijkstra to find the minimum number of walls to remove to create a connection, then carves those walls. This guarantees solvability.

What is 0-1 Dijkstra used in maze solvability?

0-1 Dijkstra is a variant where edge weights are either 0 or 1. Moving to an open passage costs 0, moving through a wall costs 1. Using a min-heap, it finds the path from start to end that requires removing the fewest walls. Standard Dijkstra works here because weights are non-negative.

What is Fisher-Yates shuffle and where do you use it?

Fisher-Yates is an algorithm for generating a uniformly random permutation of an array. We use it in Kruskal's maze to randomly shuffle all wall edges before processing them, ensuring the maze is random.

Animation & 3D

How do you animate algorithm results in 3D?

The algorithm runs synchronously and produces an array of visited nodes and the shortest path. The AnimationEngine creates a GSAP timeline that writes to shared Float32Array buffers (heights, colors, phases). The Three.js render loop reads these buffers every frame and uses spring physics to smoothly interpolate the mesh positions and colors.

What are InstancedMeshes and why do you use them?

InstancedMesh is a Three.js optimization that renders many copies of the same geometry in a single draw call. Instead of 1,250 separate mesh objects (1,250 draw calls), we have 3 InstancedMeshes (3 draw calls total) — one for roads, one for buildings, one for trees. Each instance gets its own position, scale, and color via matrix and color arrays.

What is spring physics in your animations?

Instead of linear interpolation, we simulate a spring: springForce = stiffness × displacement, dampingForce = damping × velocity. This creates natural-feeling animations with overshoot and bounce — like buildings "popping up" when placed and roads "bouncing" when the path is found.

How does the speed slider work during animation?

We adjust the GSAP timeline's timeScale property using an exponential curve: timeScale = 0.15 + (speed/100)^1.5 × 5.85. This maps the 1-100 slider to a smooth range from 0.15× (very slow) to 6× (ultra fast) without restarting the animation.

Integration & Workflow

Walk me through the complete flow when a user clicks "Run".

1) Cancel any existing animation and increment runId for concurrency safety. 2) Reset algorithm state on all grid nodes (distances to infinity, clear visited flags). 3) Run the selected algorithm synchronously — this returns visitedNodesInOrder and shortestPath arrays. 4) Create an AnimationEngine with a GSAP timeline that plays back the visited sequence with staggered delays. 5) The timeline writes to shared Float32Array buffers. 6) Three.js useFrame reads these buffers 60 times per second and uses spring physics to animate the 3D city mesh.

How do you handle race conditions when the user clicks Run multiple times?

We use a runId counter. Each new run increments it and cancels the previous AnimationEngine. All async callbacks capture the runId when they're created and check if it still matches before executing. If a newer run started, old callbacks silently exit.

How does the Share Grid feature work?

When a user clicks Share, the board layout (walls, weights, algorithm) is serialized and sent via POST to our API route. The server validates the payload and stores it in a Neon PostgreSQL database with a UUID. The user gets a shareable URL like /visualizer?share=uuid. When someone opens that URL, it fetches the layout from the database and restores it on the grid.

How does the Compare page work?

The Compare page has one shared board layout with two algorithm selectors. When you run the comparison, both algorithms execute on the same grid configuration. The results are displayed as two side-by-side animated 2D grids showing the exploration pattern, plus metrics cards and a Recharts bar chart comparing visited nodes, path length, and path cost.

Theory & Concepts

What is the difference between a graph and a tree?

A tree is a connected, acyclic graph. A graph can have cycles, multiple connected components, and edges going in any direction. Our grid is a graph (nodes can have multiple paths between them), but when we build a maze using Kruskal's or Prim's, we're essentially finding a spanning tree of the grid.

What is a spanning tree?

A spanning tree of a graph is a subgraph that includes all vertices but is a tree (no cycles). The maze generators (Prim's, Kruskal's, Backtracker) all create spanning trees of the grid graph — every cell is reachable from every other cell via exactly one path.

What is the difference between a priority queue and a regular queue?

A regular queue processes elements in FIFO order. A priority queue processes the element with the highest priority (smallest value in a min-heap). BFS uses a regular queue (process in order added). Dijkstra/A* use a priority queue (process the node closest to start / with lowest f-value first).

What is path cost vs path length?

Path length is the number of nodes in the path. Path cost is the sum of all node weights along the path (excluding the start node). On an unweighted grid, path cost = path length - 1. On a weighted grid, path cost can be much higher due to weight-5 terrain cells.

What are the limitations of your project?

Fixed 25×50 grid size, 4-directional movement only (no diagonals), no negative weight support, only Manhattan heuristic for A*, cannot modify board during animation, and the Compare page uses 2D grids instead of 3D. Also, Random Scatter maze doesn't guarantee solvability.

What would you improve in the future?

Dynamic grid sizes, 8-directional movement with Octile distance heuristic, more algorithms like Jump Point Search and Bellman-Ford, dual 3D city renderers on the Compare page, different terrain types with varied costs, step-by-step replay controls, and mobile optimization.

How would you handle diagonal movement?

Add 4 more neighbor directions: (r-1,c-1), (r-1,c+1), (r+1,c-1), (r+1,c+1). Change the heuristic from Manhattan to Octile distance: max(|Δr|, |Δc|) + (√2 - 1) × min(|Δr|, |Δc|). Diagonal moves would cost √2 ≈ 1.414 instead of 1.

Why is TypeScript important for this project?

TypeScript catches type errors at compile time. With complex data structures like GridNode, animation buffers, and state management, TypeScript ensures we don't accidentally pass wrong types, access undefined properties, or break the contract between the algorithm layer and the rendering layer.

What is glassmorphism in your UI?

Glassmorphism is a design style using frosted glass effects — translucent backgrounds with backdrop blur, subtle borders, and soft shadows. We built a custom CSS system with classes like .glass and .glass-elevated using backdrop-filter: blur() and semi-transparent backgrounds, giving the UI a premium, layered look on top of the 3D scene.

Quick Fire Round

BFS uses which data structure?

Queue (FIFO).

DFS uses which data structure?

Stack (LIFO).

What is f(n) in A*?

f(n) = g(n) + h(n) — actual cost from start plus heuristic estimate to goal.

What happens if h(n) = 0 in A*?

A* degenerates to Dijkstra's algorithm (f(n) = g(n) only).

What happens if g(n) = 0 in A*?

A* degenerates to Greedy Best-First Search (f(n) = h(n) only).

Time complexity of MinHeap push?

O(log n).

What is the weight of a weighted cell in your project?

5 (default). Normal cells have weight 1.

How many algorithms does your project support?

6 pathfinding algorithms and 5 maze generators.

What does "consistent heuristic" mean?

For every pair of nodes A and B, h(A) ≤ cost(A→B) + h(B). Manhattan distance on a 4-directional grid is consistent.
